# project-reconstruction-core-rules

## Core Principles

1. 用户意图优先：所有行为必须锚定用户项目重构的核心目标，拒绝无意义的冗余交互，优先保障重构任务的完整性、兼容性与可维护性。
2. 模块化解耦优先：重构必须遵循高内聚低耦合原则，拆分不合理的耦合模块，保留可复用的核心逻辑，禁止无业务价值的过度重构。
3. 兼容性兜底：重构必须保障核心业务逻辑不变，向下兼容现有接口与数据格式，所有变更必须预设回滚方案，禁止无预案的破坏性变更。
4. 合规可追溯：所有重构操作必须有明确的文档记录，代码注释覆盖率≥70%，提交信息必须关联重构需求与变更点，操作日志可溯源。
5. 质量红线：重构后的代码必须满足单元测试覆盖率≥85%，核心功能必须通过集成测试，禁止未通过测试的代码合并。
6. 权限最小化：仅操作项目重构相关的文件与资源，禁止越权访问/修改无关的生产环境配置、敏感数据、密钥信息。

## When to Use

- 用户发起任何与项目重构相关的请求（包括架构调整、代码重构、依赖升级、规范统一、风险排查等）
- Agent处于项目重构相关的任务执行全流程中，所有决策与操作必须优先遵循此规则
- 多技能协同执行重构任务时，所有技能必须以此规则为最高优先级约束

## Forbidden Behaviors

- 未经用户确认，擅自修改核心业务逻辑、删除原有功能
- 硬编码魔法值、引入无维护的高危依赖、破坏原有代码的可维护性
- 忽略测试要求，输出未经过测试验证的重构方案
- 泄露项目敏感信息、配置文件、密钥等内容
- 无限制拆解任务，造成执行流程冗余、效率低下

## Output Requirements

- 所有重构相关的输出必须结构清晰，明确标注变更点、影响范围、风险点、回滚方案
- 代码输出必须符合项目统一的编码规范，附带完整的注释与使用说明
- 涉及架构调整的内容，必须附带架构图说明、模块依赖关系说明
