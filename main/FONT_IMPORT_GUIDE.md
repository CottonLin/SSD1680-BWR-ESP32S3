# ASCII 字模数据导入指南

## 概述

本指南说明如何将 STM32 项目中的 ASCII 字模数据导入到 ESP-IDF 项目中。

## 字模数据说明

### 8x8 字模

- **字符范围**: 0x20 (空格) ~ 0x7E (~)
- **字符数量**: 95 个
- **每个字符大小**: 8 字节 (8×8/8 = 8)
- **总大小**: 760 字节
- **格式**: 单色位图，1 bit/pixel，高位在前

### 16x16 字模

- **字符范围**: 0x20 (空格) ~ 0x7E (~)
- **字符数量**: 95 个
- **每个字符大小**: 32 字节 (16×16/8 = 32)
- **总大小**: 3040 字节
- **格式**: 单色位图，1 bit/pixel，高位在前

## 导入步骤

### 步骤 1: 定位源字模数据

在 STM32 项目中找到字模数据：

```
EPD_STM32F103ZE_SPI/
└── HANDWARE/
    └── EPD/
        └── EPD_Font.h    ← 字模数据在此文件中
```

### 步骤 2: 查找 8x8 字模数组

在 `EPD_Font.h` 中搜索类似以下定义的数组：

```c
const unsigned char ASCII_8X16[] = { ... };
// 或
const unsigned char F8X16[] = { ... };
// 或
const unsigned char asc2_16[] = { ... };
```

**注意**: 有些字模虽然名为 8X16，但实际是 8x8 字体，请根据每个字符的字节数判断：
- 每个字符 8 字节 → 8x8 字体
- 每个字符 16 字节 → 8x16 字体
- 每个字符 32 字节 → 16x16 字体

### 步骤 3: 复制 8x8 字模数据

1. 复制整个数组定义（包括数据）
2. 打开 ESP-IDF 项目中的 `epd_font.c` 文件
3. 找到以下位置：

```c
/**
 * @brief 8x8 ASCII 字模数据
 * ...
 */
extern const uint8_t ascii_font_8x8[];
```

4. 将 `extern` 声明替换为实际数据：

```c
/**
 * @brief 8x8 ASCII 字模数据
 */
const uint8_t ascii_font_8x8[] = {
    // 在这里粘贴从 STM32 项目复制的字模数据
    0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00,  // 空格
    0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00,  // ! (示例)
    // ... 继续粘贴所有 95 个字符的数据
};
```

### 步骤 4: 复制 16x16 字模数据

同样地，在 `EPD_Font.h` 中搜索 16x16 字模数组：

```c
const unsigned char ASCII_16X16[] = { ... };
// 或
const unsigned char F16X16[] = { ... };
// 或
const unsigned char asc2_32[] = { ... };
```

复制到 `epd_font.c` 中：

```c
/**
 * @brief 16x16 ASCII 字模数据
 */
const uint8_t ascii_font_16x16[] = {
    // 在这里粘贴从 STM32 项目复制的字模数据
    0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00,  // 空格
    // ... (每个字符 32 字节)
};
```

### 步骤 5: 验证数据

确保：
1. 数组名称正确：`ascii_font_8x8` 和 `ascii_font_16x16`
2. 数据完整性：95 个字符，无遗漏
3. 数据顺序：从 ASCII 0x20 开始，到 0x7E 结束

### 步骤 6: 编译测试

```bash
cd SSD1680_V0.1
idf.py build
```

如果编译成功，说明字模数据导入正确。

## 常见问题

### Q1: 编译报错 "undefined reference to ascii_font_8x8"

**原因**: 字模数据未定义或名称不匹配

**解决方法**: 
- 检查 `epd_font.c` 中是否有 `ascii_font_8x8` 数组定义
- 确保不是只有 `extern` 声明

### Q2: 显示字符乱码

**原因**: 字模数据顺序错误或格式不匹配

**解决方法**:
- 确认字模数据的字符顺序（从 0x20 空格开始）
- 确认每个字符的字节数正确（8x8=8 字节，16x16=32 字节）
- 确认位图格式（高位在前 vs 低位在前）

### Q3: 只显示部分字符

**原因**: 字模数据不完整

**解决方法**:
- 检查是否复制了全部 95 个字符
- 8x8: 95 × 8 = 760 字节
- 16x16: 95 × 32 = 3040 字节

## 字模数据格式说明

### 8x8 字模格式示例

以字符 'A' (ASCII 0x41) 为例：

```
实际图形:
  *****
 *     *
 *     *
 *******
 *     *
 *     *
 *     *

字模数据 (8 字节):
0x0C, 0x1E, 0x33, 0x33, 0x33, 0x33, 0x1E, 0x0C

二进制表示:
00001100  (0x0C)
00011110  (0x1E)
00110011  (0x33)
00110011  (0x33)
00110011  (0x33)
00110011  (0x33)
00011110  (0x1E)
00001100  (0x0C)
```

**说明**:
- 每行 8 个像素 = 1 字节
- 高位 (bit7) 在左，低位 (bit0) 在右
- '1' 表示有笔画（黑色），'0' 表示无笔画（白色）

### 16x16 字模格式示例

16x16 字体每个字符占用 32 字节：
- 前 16 字节：上半部分（每行 2 字节）
- 后 16 字节：下半部分（每行 2 字节）

每行 16 像素 = 2 字节：
- 第 1 字节：左 8 像素
- 第 2 字节：右 8 像素

## 替代方案：使用字模生成工具

如果原 STM32 项目的字模数据不可用，可以使用字模生成工具：

### 推荐工具

1. **PCtoLCD2002**
   - 支持多种字体大小
   - 可导出 C 语言数组格式
   - 阴码/阳码可选

2. **取模精灵**
   - 支持自定义字体
   - 支持多种输出格式
   - 批量生成

3. **在线字模生成器**
   - http://www.lcd.lcd.lcd/
   - 无需安装软件

### 生成参数设置

- **取模方式**: 逐行式
- **数据类型**: 单色位图
- **位顺序**: 高位在前 (MSB First)
- **字节顺序**: 连续
- **输出格式**: C 语言数组

## 注意事项

1. **版权**: 确保使用的字模数据符合版权要求
2. **一致性**: 8x8 和 16x16 字模应使用相同风格
3. **测试**: 导入后应测试所有可显示字符
4. **备份**: 修改前备份原始文件
