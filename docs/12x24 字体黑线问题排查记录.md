# SSD1680 12x24 字体黑线问题排查记录

## 问题描述

在 ESP-IDF V5.5 平台移植 STM32 SSD1680 墨水屏驱动时，使用 12x24 字体显示字符串时出现**黑色竖线**。

### 问题现象

- 使用 6x8、6x12、8x16 字体显示正常
- 切换到 12x24 字体时，字符之间出现黑色竖线
- 黑线位置固定在字符间隔处
- 调整 Y 坐标后，黑线会跟随移动

## 排查过程

### 第 1 步：排除显存重叠问题

**假设**：不同字体渲染时显存地址重叠，导致数据污染

**测试方法**：
1. 计算各字体的显存地址范围
2. 调整 Y 坐标，确保显存不重叠
3. 单独测试 12x24 字体

**测试结果**：
```
原始坐标：
- 6x8:   Y=10,  显存地址 191-306
- 6x12:  Y=25,  显存地址 193-327
- 8x16:  Y=45,  显存地址 195-368
- 12x24: Y=65,  显存地址 198-391  ← 与前面字体重叠

优化坐标：
- 6x8:   Y=10,  内部 X[10-17]
- 6x12:  Y=30,  内部 X[30-41]
- 8x16:  Y=55,  内部 X[55-70]
- 12x24: Y=85,  内部 X[85-108]  ← 完全不重叠
```

**结论**：显存重叠不是根本原因（调整坐标后黑线仍存在）

### 第 2 步：检查字模数据解析逻辑

**假设**：字模数据的字节顺序或 bit 顺序错误

**测试方法**：
1. 手动解析字模数据，直接写入显存
2. 对比 `epd_show_char` 函数的渲染结果
3. 尝试不同的字节序和 bit 序组合

**测试结果**：
- 手动解析显示正常
- `epd_show_char` 函数显示正常
- 字模数据格式：**高位在前 + 正常字节序**是正确的

**结论**：字模解析逻辑正确

### 第 3 步：检查字符串渲染逻辑

**假设**：字符间距过小导致像素重叠

**分析**：
- 12x24 字体的字模宽度是 12 像素
- 但某些字符（如 "1"、"T" 等）的**实际有效宽度**接近 12 像素
- 原代码字符间距 = `font->width`（12 像素），没有留余量
- 相邻字符的边缘像素可能重叠

**验证方法**：
```c
// 原代码
offset_x += font->width;  // 12 像素

// 修改后
offset_x += font->width + 1;  // 13 像素（增加 1 像素间距）
```

**测试结果**：✅ **黑线消失！**

## 问题根因

**根本原因**：字符间距过小导致相邻字符边缘像素重叠

**详细分析**：

12x24 字体的字模数据格式：
- 每行 2 字节（12 位，高位在前）
- 共 24 行
- 总计 48 字节/字符

虽然字模宽度定义为 12 像素，但某些字符的实际墨迹会延伸到接近边缘：

```
字符 "1" 的字模数据（第 6 行）：0x3F, 0xC0
二进制：00111111 11000000
有效列：列 2-9（共 8 列黑色）

字符 "T" 的字模数据（第 1 行）：0x00, 0x00, ..., 0xFF, 0x00
顶部横线可能占满 12 列
```

当两个这样的字符紧挨着时（间距 12 像素）：
- 前一个字符的最右列（列 11）可能有墨迹
- 后一个字符的最左列（列 0）可能有墨迹
- 两列重叠，形成黑色竖线

## 解决方案

### 方案 1：增加字符间距（推荐）✅

修改文件：`main/epd_gui.c`

```c
void epd_show_string(epd_canvas_t *canvas, uint16_t x, uint16_t y, 
                     const char *str, const epd_font_t *font, uint16_t color)
{
    uint16_t offset_x = 0;
    
    if (canvas == NULL || font == NULL || str == NULL) {
        return;
    }
    
    while (*str != '\0') {
        epd_show_char(canvas, x + offset_x, y, *str, font, color);
        // 增加 1 像素字符间距，避免字符间黑线
        offset_x += font->width + 1;
        str++;
    }
}
```

**优点**：
- 简单有效，只需修改 1 行代码
- 适用于所有字体（6x8、6x12、8x16、12x24）
- 不影响单个字符的渲染质量

**缺点**：
- 字符串总宽度略微增加（每个字符 +1 像素）

### 方案 2：优化字模数据（备选）

重新生成字模数据，确保每个字符的左右各留 1 像素空白。

**优点**：
- 保持原始字符间距
- 字模数据更规范

**缺点**：
- 需要重新生成字模
- 工作量大，容易出错

## 经验总结

### 1. 嵌入式字体渲染的常见问题

在点阵字体渲染中，以下问题容易导致显示异常：

| 问题类型 | 现象 | 排查方法 |
|---------|------|---------|
| 显存重叠 | 随机位置黑线/黑块 | 计算显存地址范围，确保不重叠 |
| 字节序错误 | 字符镜像/变形 | 对比手动解析和函数渲染结果 |
| Bit 序错误 | 字符左右翻转 | 尝试 0x80>>bit 和 0x01<<bit |
| 字符间距过小 | 字符间黑线 | 增加间距验证 |

### 2. SSD1680 显存映射特点

SSD1680 驱动 IC 的显存映射规则：
- **用户坐标 (x, y)** → **内部坐标 (y, x)**（旋转 90 度）
- 显存地址 = `(internal_x / 8) + (internal_y * width_bytes)`
- Bit 掩码 = `0x80 >> (internal_x % 8)`（高位在前）

### 3. 字模数据格式识别

**行列式字模**（如 12x24）：
- 存储格式：每行 `(width+7)/8` 字节，共 `height` 行
- 12x24 字体：每行 2 字节，共 24 行，总计 48 字节
- Bit 顺序：通常是高位在前（bit7 对应第 1 列）

**列行式字模**：
- 存储格式：每列 `(height+7)/8` 字节，共 `width` 列
- 解析时需要按列读取

### 4. 调试技巧

1. **隔离测试**：单独测试单个字符，排除字符串间距干扰
2. **手动解析**：绕过渲染函数，直接操作显存验证字模数据
3. **地址分析**：计算显存地址范围，定位重叠区域
4. **坐标变换**：理解用户坐标和内部坐标的映射关系

```c
// 计算字体渲染的显存地址范围
uint16_t start_x = 10;
uint16_t start_y = 65;
uint16_t internal_x = start_y;  // 坐标变换
uint16_t internal_y = start_x;

uint32_t start_addr = (internal_x / 8) + (internal_y * 19);  // 19 = 152/8
uint32_t end_addr = ((internal_x + 23) / 8) + ((internal_y + 10) * 19);

ESP_LOGI(TAG, "显存地址范围：0x%04X - 0x%04X", start_addr, end_addr);
```
