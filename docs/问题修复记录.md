## 2. 显示问题

### 2.1 全屏红色显示异常

**问题日期**: 2026-03-02  
**状态**: ✅ 已解决

**问题现象**: 整个屏幕显示为红色，而不是预期的白色背景。

**原因**: SSD1680 红色显存的数据逻辑与预期不符。原始代码认为 0xFF=不显示红色，0x00=显示红色，实际上需要对红色数据进行取反。

**解决方案**:
```c
// 写入红色显存时，对数据进行取反
static uint8_t s_red_temp[EPD_BUFFER_SIZE];
memcpy(s_red_temp, buffer_red, EPD_BUFFER_SIZE);
for (int i = 0; i < EPD_BUFFER_SIZE; i++) {
    s_red_temp[i] = ~s_red_temp[i];  // 取反
}
epd_write_data_batch(handle, s_red_temp, EPD_BUFFER_SIZE);
```

**修改文件**: `components/epd_driver/src/epd_driver.c`

### 2.2 图形错位和重影

**问题日期**: 2026-03-02  
**状态**: ✅ 已解决

**问题现象**:
- 绘制的图形出现在错误的位置
- 右侧出现重复的图形图案和虚线痕迹

**原因**: 用户坐标系 (296×152) 与 SSD1680 内部显存坐标系 (152×296) 映射不正确。

**解决方案**:
```c
// 正确的坐标转换
// 用户 X (水平 0-295) → 内部 Y (行号 0-295)，不反转
// 用户 Y (垂直 0-151) → 内部 X (列位 0-151)，需要反转
*internal_x = (canvas->internal_width - 1) - user_y;  // 151 - user_y
*internal_y = user_x;                                  // user_x

// 正确的地址计算公式
byte_addr = (internal_y * canvas->width_bytes) + (internal_x / 8);
```

**修改文件**: `components/epd_gui/src/epd_gui.c`

### 2.3 红色显示功能实现

**问题日期**: 2026-03-01  
**状态**: ✅ 已解决

**问题背景**: 用户发现屏幕上显示的字体和几何图形都是黑色的，询问如何显示红色。

**原因**: 
1. 单缓冲区设计，无法同时控制黑白和红色两个显示通道
2. 缺少 `EPD_COLOR_RED` 颜色定义
3. 像素设置逻辑不支持红色通道

**解决方案**: 实现双缓冲区架构

```c
// 画布结构体
typedef struct {
    uint8_t *buffer_bw;         // 黑白显存缓冲区
    uint8_t *buffer_red;        // 红色显存缓冲区
    uint16_t width;
    uint16_t height;
    // ...
} epd_canvas_t;

// 颜色定义
#define EPD_COLOR_WHITE     0xFF    // 白色
#define EPD_COLOR_BLACK     0x00    // 黑色
#define EPD_COLOR_RED       0x01    // 红色

// 像素设置逻辑
void epd_canvas_set_pixel(epd_canvas_t *canvas, uint16_t x, uint16_t y, uint16_t color)
{
    if (color == EPD_COLOR_BLACK) {
        // 黑色：黑白通道=0，红色通道=1
        canvas->buffer_bw[byte_addr] &= ~bit_mask;
        if (canvas->buffer_red != NULL) {
            canvas->buffer_red[byte_addr] |= bit_mask;
        }
    } else if (color == EPD_COLOR_RED) {
        // 红色：黑白通道=1，红色通道=0
        canvas->buffer_bw[byte_addr] |= bit_mask;
        if (canvas->buffer_red != NULL) {
            canvas->buffer_red[byte_addr] &= ~bit_mask;
        }
    } else {
        // 白色：两个通道都为 1
        canvas->buffer_bw[byte_addr] |= bit_mask;
        if (canvas->buffer_red != NULL) {
            canvas->buffer_red[byte_addr] |= bit_mask;
        }
    }
}
```

- `components/epd_gui/include/epd_gui.h`
- `components/epd_gui/src/epd_gui.c`
- `main/main.c`

## 3. 字体渲染问题

### 3.1 12x24 字体黑线问题

**问题日期**: 2026-03-01  
**状态**: ✅ 已解决

**问题现象**:
- 使用 6x8、6x12、8x16 字体显示正常
- 切换到 12x24 字体时，字符之间出现黑色竖线
- 黑线位置固定在字符间隔处

**排查过程**:
1. ❌ 排除显存重叠问题 - 调整坐标后黑线仍存在
2. ✅ 检查字模数据解析逻辑 - 字模解析逻辑正确
3. ✅ 检查字符串渲染逻辑 - 发现字符间距过小

**根本原因**: 字符间距过小导致相邻字符边缘像素重叠。12x24 字体的字模宽度是 12 像素，但某些字符（如 "1"、"T" 等）的实际有效宽度接近 12 像素，原代码字符间距 = `font->width`（12 像素），没有留余量。

**解决方案**:
```c
// 修复前
offset_x += font->width;  // 12 像素

// 修复后
offset_x += font->width + 1;  // 13 像素（增加 1 像素间距）
```

**修改文件**: `components/epd_gui/src/epd_gui.c`

**经验总结**: 在点阵字体渲染中，字符间距需要考虑字符的实际墨迹宽度，而非字模定义宽度。

## 5. 坐标系统问题

### 5.1 文本显示位置颠倒

**问题日期**: 2026-03-01  
**状态**: ✅ 已解决

**问题现象**: 文本显示位置颠倒，本应显示在下方的文本显示在了上方。

**原因**: 坐标转换只做了转置（旋转 90 度），没有进行 Y 轴镜像翻转。

**原始代码**:
```c
// ❌ 错误的坐标转换
static inline void coordinate_transform(epd_canvas_t *canvas, 
                                        uint16_t user_x, uint16_t user_y,
                                        uint16_t *internal_x, uint16_t *internal_y)
{
    *internal_x = user_y;
    *internal_y = user_x;  // 问题：仅做转置，未做 Y 轴翻转
}
```

**解决方案**:
```c
// ✅ 正确的坐标转换
static inline void coordinate_transform(epd_canvas_t *canvas, 
                                        uint16_t user_x, uint16_t user_y,
                                        uint16_t *internal_x, uint16_t *internal_y)
{
    *internal_x = user_y;
    *internal_y = (EPD_HEIGHT - 1) - user_x;  // Y 轴翻转：EPD_HEIGHT = 296
}
```

**转换逻辑**:
- 用户坐标 `user_x = 0`（顶部）→ 内部坐标 `internal_y = 295`（底部）
- 用户坐标 `user_x = 295`（底部）→ 内部坐标 `internal_y = 0`（顶部）

**修改文件**: `components/epd_gui/src/epd_gui.c`

### 5.2 字符级别换行切断单词

**问题日期**: 2026-03-01  
**状态**: ✅ 已解决

**问题现象**: 长单词在行尾被切断，影响可读性。

**示例**:
```
原始文本："Hello World Test"
换行后：
行 1: "Hello Worl"  ← 单词 "World" 被切断 ❌
行 2: "d Test"
```

**原因**: 初始实现以单个字符为单位判断是否换行，没有预计算单词的总宽度。

**原始代码**:
```c
// ❌ 字符级别换行
while (*str != '\0') {
    if (current_x + font->width > max_width) {
        current_x = x;
        current_y += line_height;
    }
    
    epd_show_char(canvas, current_x, current_y, *str, font, color);
    current_x += font->width + 1;
    str++;
}
```

**解决方案**: 实现单词级别智能换行

```c
// ✅ 计算单词宽度
static uint16_t calculate_string_width(const char *str, const epd_font_t *font)
{
    uint16_t width = 0;
    const char *p = str;
    
    while (*p != '\0' && *p != ' ' && *p != '\n') {
        width += font->width;
        p++;
    }
    
    return width;
}

// ✅ 单词级别换行
while (*str != '\0') {
    // 1. 遇到换行符 → 强制换行
    if (*str == '\n') {
        current_x = x;
        current_y += line_height;
        str++;
        continue;
    }
    
    // 2. 遇到空格 → 显示空格并更新位置
    if (*str == ' ') {
        current_x += font->width + char_spacing;
        str++;
        continue;
    }
    
    // 3. 遇到单词 → 先计算宽度，判断是否需要换行
    word_width = calculate_string_width(str, font);
    remaining_width = max_width - current_x;
    
    // 智能判断：单词宽度 > 剩余宽度 → 先换行
    if (word_width > remaining_width && current_x > x) {
        current_x = x;
        current_y += line_height;
    }
    
    // 4. 显示整个单词
    while (*str != '\0' && *str != ' ' && *str != '\n') {
        epd_show_char(canvas, current_x, current_y, *str, font, color);
        current_x += font->width + char_spacing;
        str++;
    }
}
```

**对比效果**:
| 换行方式 | 示例 | 效果 |
|---------|------|------|
| **字符级别** | `"Hello Worl"` + `"d Test"` | ❌ 单词被切断 |
| **单词级别** | `"Hello"` + `"World Test"` | ✅ 保持单词完整 |

**修改文件**: `components/epd_gui/src/epd_gui.c`
