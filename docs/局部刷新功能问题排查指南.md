## 问题概述

### 目标
为 SSD1680 三色电子墨水屏项目添加局部刷新功能，实现：
- 黑白内容使用局部刷新（耗时 1-3 秒）
- 红色内容使用全屏刷新（耗时 30 秒）
- 提升显示效率 10-30 倍

### 当前状态
- ✅ 代码编译通过，无语法错误
- ✅ 局部刷新函数被正确调用
- ✅ 坐标转换逻辑已统一
- ✅ 红色内容检测逻辑正确
- ❌ **屏幕对局部刷新无响应（黑屏/白屏，无显示）**

## 问题排查时间线

### 阶段 1：红色显存干扰问题

#### 问题 1.1：红色显存误写入导致黑白内容被覆盖

**现象**：
- 黑白内容显示时屏幕无内容或显示异常
- 日志显示红色显存被写入

**根本原因**：
- `epd_display()` 每次都写入红色显存
- 红色缓冲区全白（0xFF）取反后变成全黑（0x00）
- 红色通道意外启用，覆盖黑白显示内容

**解决方案**：
```c
// 修改 epd_display() 判断逻辑
if (buffer_red != NULL && buffer_red != buffer_bw) {
    // 写入红色显存
} else {
    ESP_LOGI(TAG, "无红色内容，跳过红色显存写入");
}
```

**状态**: ✅ 已修复

---

#### 问题 1.2：红色缓冲区未初始化导致误判

**现象**：
- 红色内容检测随机触发
- 缓冲区包含随机数据

**根本原因**：
- `malloc()` 分配的内存未初始化
- 包含随机垃圾数据

**解决方案**：
```c
// 创建画布后立即初始化红色缓冲区
test_buffer_red = malloc(EPD_BUFFER_SIZE);
memset(test_buffer_red, 0xFF, EPD_BUFFER_SIZE);  // 初始化为白色
```

**状态**: ✅ 已修复

---

#### 问题 1.3：SSD1680 红色 RAM 未初始化导致红色噪点

**现象**：
- 屏幕显示满屏红色噪点
- "Hello" 文字显示正常，但背景有红色噪点

**根本原因**：
- SSD1680 上电后红色 RAM 是随机值（不是 0xFF）
- 首次清屏时跳过红色显存写入
- 红色 RAM 保持随机值，刷新后显示为红色噪点

**解决方案**：
```c
// 首次清屏必须写入红色显存
memset(test_buffer_bw, 0xFF, EPD_BUFFER_SIZE);
memset(test_buffer_red, 0xFF, EPD_BUFFER_SIZE);
epd_display(test_buffer_bw, test_buffer_red);  // 初始化 SSD1680 红色 RAM
```

**状态**: ✅ 已修复

---

### 阶段 2：坐标系统问题

#### 问题 2.1：坐标转换不一致导致显示位置错误

**现象**：
- GUI 层绘制的内容与局部刷新的位置不匹配
- 屏幕显示内容偏移或完全不显示

**根本原因**：
- GUI 层坐标转换：`internal_x = (EPD_WIDTH - 1) - user_y`（有翻转）
- 局部刷新坐标转换：`internal_x = user_y`（无翻转）
- 两层使用不同的坐标系统

**解决方案**：
```c
// 统一坐标转换逻辑（与 GUI 层一致）
internal_rect->x_start = (EPD_WIDTH - 1) - user_rect->y_end;
internal_rect->x_end   = (EPD_WIDTH - 1) - user_rect->y_start;
internal_rect->y_start = user_rect->x_start;
internal_rect->y_end   = user_rect->x_end;
```

**状态**: ✅ 已修复

---

#### 问题 2.2：地址计算方式不统一

**现象**：
- 局部刷新写入的数据与实际显示位置不匹配

**根本原因**：
- GUI 层地址计算：`byte_addr = (internal_x / 8) + (internal_y * width_bytes)`
- 局部刷新地址计算：`index = y * (EPD_WIDTH / 8) + x`
- 两种计算方式导致地址偏移

**解决方案**：
```c
// 统一使用 GUI 层的地址计算方式
uint32_t byte_addr = x + (y * (EPD_WIDTH / 8));
epd_write_data(data_buffer[byte_addr]);
```

**状态**: ✅ 已修复

### 阶段 3：红色内容检测问题

#### 问题 3.1：红色内容检测误判

**现象**：
- 绘制黑白内容时日志显示"检测到红色内容，强制全屏刷新"
- 局部刷新被强制切换为全屏刷新

**根本原因**：
- 红色缓冲区使用内部坐标计算地址
- GUI 层使用不同的地址计算方式
- 地址计算不匹配导致误检测

**解决方案**：
```c
// 简化检测逻辑：直接遍历整个缓冲区
for (uint32_t i = 0; i < EPD_BUFFER_SIZE; i++) {
    if (buffer_red[i] != 0xFF) {
        return true;
    }
}
```

**状态**: ✅ 已修复

---

#### 问题 3.2：绘制黑色内容时错误修改红色缓冲区

**现象**：
- 局部刷新测试总是调用全屏刷新
- 红色检测一直返回 true

**根本原因**：
- `epd_canvas_set_pixel()` 在绘制黑色内容时修改了红色缓冲区
- 导致红色缓冲区从 0xFF 变成非 0xFF 的值
- 红色检测误判为有红色内容

**错误代码**：
```c
if (color == EPD_COLOR_BLACK) {
    canvas->buffer_bw[byte_addr] &= ~bit_mask;
    if (canvas->buffer_red != NULL) {
        canvas->buffer_red[byte_addr] |= bit_mask;  // ← 错误！
    }
}
```

**解决方案**：
```c
if (color == EPD_COLOR_BLACK) {
    canvas->buffer_bw[byte_addr] &= ~bit_mask;
    // 红色通道：黑色内容不修改红色通道（保持原值）
    // 注意：不要修改 buffer_red，否则会影响红色内容检测
}
```

**状态**: ✅ 已修复

### 阶段 4：刷新命令和时序问题

#### 问题 4.1：局部刷新函数没有写入显存数据

**现象**：
- 日志显示局部刷新完成，但屏幕无显示
- 只发送了刷新命令，没有写入显存数据

**根本原因**：
- `epd_partial_refresh_bw()` 只设置了刷新区域和发送命令
- **缺少显存数据写入步骤**
- SSD1680 收到刷新命令但显存没有新数据

**解决方案**：
```c
// 增加显存数据写入步骤
epd_write_cmd(SSD1680_WRITE_RAM_BW);
for (逐行扫描区域) {
    epd_write_data(data_buffer[byte_addr]);
}
```

**状态**: ✅ 已修复（代码层面）

---

#### 问题 4.2：局部刷新延时不足

**现象**：
- 步骤 3 和 4 的日志在全刷完成前就打印了
- 局部刷新的延时太短（300ms），但代码继续执行太快

**根本原因**：
- SSD1680 的局部刷新实际耗时可能是 1-2 秒
- 300ms 后屏幕还在刷新，代码就已经继续执行下一步了

**解决方案**：
```c
// 增加延时到 2 秒
vTaskDelay(pdMS_TO_TICKS(2000));
```

**状态**: ✅ 已修复

---

#### 问题 4.3：使用了错误的刷新命令

**现象**：
- 步骤 2 显示 "Hello" 后快速跳过
- 步骤 3 和 4 被跳过，没有显示

**根本原因**：
- 使用了 `SSD1680_MASTER_ACTIVATION (0x20)` 命令
- 这是**全屏刷新命令**，不是局部刷新命令
- 实际触发的是 30 秒全刷

**错误代码**：
```c
epd_write_cmd(SSD1680_MASTER_ACTIVATION);  // 0x20 = 全刷
```

**解决方案**：
```c
epd_write_cmd(0x21);  // PARTIAL_REFRESH（局刷命令）
```

**状态**: ✅ 已修复（代码层面）

---

#### 问题 4.4：步骤 5 测试逻辑错误

**现象**：
- 步骤 5 的局部刷新调用了 30 秒全刷

**根本原因**：
1. 步骤 4 绘制红色文字后，红色缓冲区被修改
2. 步骤 5 没有清空红色缓冲区
3. 红色检测误判，强制全刷

**解决方案**：
```c
// 重构步骤 5 测试逻辑
// 1. 先全刷清屏一次
memset(test_buffer_bw, 0xFF, EPD_BUFFER_SIZE);
memset(test_buffer_red, 0xFF, EPD_BUFFER_SIZE);
epd_display(test_buffer_bw, test_buffer_red);

// 2. 连续 10 次局部刷新（不先全刷）
for (int i = 0; i < 10; i++) {
    epd_show_string_ex(canvas, 10, 90, text, font, EPD_COLOR_BLACK, EPD_REFRESH_PARTIAL_BW);
}
```

**状态**: ✅ 已修复

## 待解决的问题

### 问题 5.1：局部刷新命令 `0x21` 无效

**现象**：
- 日志显示局部刷新命令已发送
- 屏幕对局部刷新无响应（黑屏/白屏，无显示）
- Hello 也没有显示

**可能的原因**：

#### 原因 A：`0x21` 命令需要 LUT 配置
SSD1680 的 `PARTIAL_REFRESH (0x21)` 命令通常需要预先配置 LUT（Look-Up Table）寄存器。我们没有配置 LUT，导致命令无效。

**验证方法**：
- 查阅 SSD1680 数据手册，确认 `0x21` 命令的 LUT 要求
- 检查初始化代码中是否有 LUT 配置

**可能的解决方案**：
```c
// 在 epd_init() 中添加 LUT 配置
void epd_init_partial_refresh_lut(void)
{
    epd_write_cmd(0x32);  // LUT 寄存器
    // 写入局部刷新专用的 LUT 数据
    // ...
}
```

---

#### 原因 B：`0x21` 命令不需要 `DISPLAY_UPDATE_CTRL_2`
查看 SSD1680 数据手册，`0x21` 命令可能是独立命令，不需要先发送 `0x22`。

**当前代码**：
```c
epd_write_cmd(SSD1680_DISPLAY_UPDATE_CTRL_2);
epd_write_data(0xF7);
epd_write_cmd(0x21);  // PARTIAL_REFRESH
```

**可能的修复**：
```c
epd_write_cmd(0x21);  // 直接发送局刷命令
```

---

#### 原因 C：区域地址设置后需要重置计数器
写入显存数据前，可能需要重新设置 RAM 地址计数器。

**当前代码**：
```c
epd_set_refresh_area_internal(&internal_rect);
// 直接写入数据
epd_write_cmd(SSD1680_WRITE_RAM_BW);
```

**可能的修复**：
```c
epd_set_refresh_area_internal(&internal_rect);
// 重新设置计数器
epd_write_cmd(SSD1680_SET_RAM_X_ADDRESS_COUNTER);
epd_write_data((internal_rect.x_start >> 3) & 0x1F);
epd_write_cmd(SSD1680_SET_RAM_Y_ADDRESS_COUNTER);
epd_write_data(internal_rect.y_start & 0xFF);
// 然后写入数据
```

---

#### 原因 D：局部刷新波形配置缺失
SSD1680 的局部刷新需要在初始化时配置特殊的波形参数。

**可能的解决方案**：
```c
// 在 epd_init() 中添加
epd_write_cmd(0x04);  // 写入局部刷新波形配置
epd_write_data(0x07);
```

## 技术要点总结

### 1. SSD1680 三色屏特性

- **局部刷新仅支持黑白内容**，红色内容必须使用全屏刷新
- **红色 RAM 上电后是随机值**，必须显式初始化
- **纯黑白显示时可以跳过红色显存写入**（优化性能）
- **首次清屏必须写入红色显存**（初始化 SSD1680 RAM）

### 2. 坐标系统

- **用户坐标**：296x152（横向）
- **内部坐标**：152x296（纵向，SSD1680 RAM 坐标）
- **转换公式**：
  ```c
  internal_x = (EPD_WIDTH - 1) - user_y;
  internal_y = user_x;
  ```

### 3. 显存管理

- **地址计算**：`byte_addr = (internal_x / 8) + (internal_y * width_bytes)`
- **宽度字节数**：`width_bytes = EPD_WIDTH / 8 = 152 / 8 = 19`
- **红色检测**：遍历整个缓冲区，检查是否有非 0xFF 的数据

### 4. 颜色通道逻辑

| 颜色 | 黑白通道 | 红色通道 |
|------|---------|---------|
| **黑色** | 写入 0 | **不修改**（保持 0xFF） |
| **红色** | 写入 1（白色） | 写入 0 |
| **白色** | 写入 1 | 写入 1 |

### 5. 局刷保护机制

- 每 8 次局部刷新后自动全屏刷新
- 防止残影累积

## 下一步建议

### 1. 验证 `0x21` 命令的正确用法

**步骤**：
1. 查阅 SSD1680 数据手册，确认 `0x21` 命令的完整序列
2. 检查是否需要 LUT 配置
3. 检查是否需要特殊的波形参数

**参考代码结构**：
```c
void epd_partial_refresh_bw(const epd_rect_t *rect, const uint8_t *buffer_bw)
{
    // 1. 设置刷新区域
    epd_set_refresh_area_internal(&internal_rect);
    
    // 2. 重新设置地址计数器
    epd_write_cmd(SSD1680_SET_RAM_X_ADDRESS_COUNTER);
    epd_write_data(...);
    epd_write_cmd(SSD1680_SET_RAM_Y_ADDRESS_COUNTER);
    epd_write_data(...);
    
    // 3. 写入显存数据
    epd_write_cmd(SSD1680_WRITE_RAM_BW);
    // ...
    
    // 4. 发送局部刷新命令（可能需要 LUT 配置）
    epd_write_cmd(0x21);
    
    // 5. 等待刷新完成（可能需要更长时间）
    vTaskDelay(pdMS_TO_TICKS(3000));
}
```

### 2. 添加 BUSY 引脚检测

如果硬件连接了 BUSY 引脚，可以读取 BUSY 状态而不是固定延时：

```c
void epd_wait_busy_partial(void)
{
    int timeout = 0;
    while (gpio_get_level(BUSY_PIN) == 0) {
        vTaskDelay(pdMS_TO_TICKS(10));
        timeout += 10;
        if (timeout > 5000) {
            ESP_LOGE(TAG, "等待局部刷新超时");
            break;
        }
    }
}
```

### 3. 尝试使用全屏刷新命令 + 快速波形

如果 `0x21` 命令确实需要复杂的 LUT 配置，可以考虑：
- 使用全屏刷新命令（`0x20`）
- 但配置快速波形参数
- 实现"伪局部刷新"（刷新整个屏幕但使用快速波形）

### 4. 参考厂商提供的例程

查找 SSD1680 厂商提供的局部刷新例程，参考其：
- LUT 配置参数
- 刷新命令序列
