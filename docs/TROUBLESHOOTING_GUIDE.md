# SSD1680 字符串显示问题排查与解决文档

在实现 SSD1680 墨水屏字符串自动换行功能时，遇到了一系列问题。本文档记录了问题的发现、分析、解决过程和经验总结。

## 🔍 问题 1：坐标系统方向错误

### 问题现象
- **症状**：文本显示位置颠倒，本应显示在下方的文本显示在了上方
- **发现时机**：实现自动换行功能后测试发现
- **影响**：换行时 Y 坐标增加，但文本向上移动而非向下移动

### 原因分析

#### 1. SSD1680 坐标系统特性
SSD1680 控制器的坐标系统与常规 GUI 系统不同：
- **用户坐标系**：物理屏幕，X[0-295], Y[0-151]，Y 轴向下为正
- **内部坐标系**：SSD1680 RAM，X[0-151], Y[0-295]，Y 轴方向与用户坐标相反

#### 2. 原始代码问题
```c
// ❌ 错误的坐标转换
static inline void coordinate_transform(epd_canvas_t *canvas, 
                                        uint16_t user_x, uint16_t user_y,
                                        uint16_t *internal_x, uint16_t *internal_y)
{
    *internal_x = user_y;
    *internal_y = user_x;  // 问题：仅做转置，未做 Y 轴翻转
}
```

**问题根源**：
- 只做了坐标转置（旋转 90 度）
- 没有进行 Y 轴镜像翻转
- 导致用户坐标的 Y 轴正方向与 SSD1680 内部坐标的 Y 轴正方向不一致

### 解决方案

```c
// ✅ 正确的坐标转换
static inline void coordinate_transform(epd_canvas_t *canvas, 
                                        uint16_t user_x, uint16_t user_y,
                                        uint16_t *internal_x, uint16_t *internal_y)
{
    *internal_x = user_y;
    *internal_y = (EPD_HEIGHT - 1) - user_x;  // Y 轴翻转：EPD_HEIGHT = 296
}
```

**转换逻辑**：
- 用户坐标 `user_x = 0`（顶部）→ 内部坐标 `internal_y = 295`（底部）
- 用户坐标 `user_x = 295`（底部）→ 内部坐标 `internal_y = 0`（顶部）

### 验证结果
- ✅ 文本从上到下正确显示
- ✅ 换行时 Y 坐标增加，文本向下移动
- ✅ 符合常规 GUI 的视觉习惯

### 经验教训
1. **坐标系统映射**：在不同坐标系间转换时，必须考虑轴的方向
2. **硬件差异**：显示控制器的坐标系统可能与常规 GUI 系统不同
3. **早期测试**：坐标转换应该在项目早期就验证，避免后期发现问题

## 🔍 问题 2：字符级别换行切断单词

### 问题现象
- **症状**：长单词在行尾被切断，影响可读性
- **示例**：
  ```
  原始文本："Hello World Test"
  换行后：
  行 1: "Hello Worl"  ← 单词 "World" 被切断 ❌
  行 2: "d Test"
  ```

### 原因分析

#### 1. 初始实现逻辑
```c
// ❌ 字符级别换行
while (*str != '\0') {
    // 每个字符都检查是否超出右边界
    if (current_x + font->width > max_width) {
        current_x = x;
        current_y += line_height;
    }
    
    epd_show_char(canvas, current_x, current_y, *str, font, color);
    current_x += font->width + 1;
    str++;
}
```

#### 2. 问题根源
- **判断粒度太细**：以单个字符为单位判断是否换行
- **缺乏预计算**：没有提前计算单词的总宽度
- **无单词概念**：无法识别单词的完整性

### 解决方案

#### 1. 新增单词宽度计算函数
```c
// ✅ 计算单词宽度
static uint16_t calculate_string_width(const char *str, const epd_font_t *font)
{
    uint16_t width = 0;
    const char *p = str;
    
    // 计算从当前位置到下一个空格/换行符的宽度
    while (*p != '\0' && *p != ' ' && *p != '\n') {
        width += font->width;
        p++;
    }
    
    return width;
}
```

#### 2. 智能换行逻辑
```c
// ✅ 单词级别换行
while (*str != '\0') {
    // 1. 遇到换行符 → 强制换行
    if (*str == '\n') {
        current_x = x;
        current_y += line_height;
        str++;
        continue;
    }
    
    // 2. 遇到空格 → 显示空格并更新位置
    if (*str == ' ') {
        current_x += font->width + char_spacing;
        str++;
        continue;
    }
    
    // 3. 遇到单词 → 先计算宽度，判断是否需要换行
    word_width = calculate_string_width(str, font);
    remaining_width = max_width - current_x;
    
    // 智能判断：单词宽度 > 剩余宽度 → 先换行
    if (word_width > remaining_width && current_x > x) {
        current_x = x;
        current_y += line_height;
    }
    
    // 4. 显示整个单词
    while (*str != '\0' && *str != ' ' && *str != '\n') {
        epd_show_char(canvas, current_x, current_y, *str, font, color);
        current_x += font->width + char_spacing;
        str++;
    }
}
```

### 对比效果

| 换行方式 | 示例 | 效果 |
|---------|------|------|
| **字符级别** | `"Hello Worl"` + `"d Test"` | ❌ 单词被切断 |
| **单词级别** | `"Hello"` + `"World Test"` | ✅ 保持单词完整 |

### 验证结果
- ✅ 长单词不会被切断
- ✅ 换行位置在单词之间
- ✅ 文本可读性大幅提升

### 经验教训
1. **语义化换行**：应该按语义单元（单词）换行，而非字符
2. **预计算优化**：提前计算需要的数据，避免盲目处理
3. **用户体验**：微小的改进能显著提升可读性

## 🛠️ 技术要点总结

### 1. 坐标系统转换

#### 关键公式
```
内部 X = 用户 Y
内部 Y = (EPD_HEIGHT - 1) - 用户 X
```

#### 注意事项
- SSD1680 的 RAM 组织方式与物理屏幕不同
- 必须进行坐标转置和 Y 轴翻转
- 坐标转换会影响所有图形绘制操作

### 2. 智能换行算法

#### 核心思想
```
1. 识别单词边界（空格、换行符）
2. 预计算单词宽度
3. 判断：单词宽度 > 剩余空间 → 换行
4. 保持单词完整性
```

#### 边界情况处理
| 情况 | 处理方式 |
|------|---------|
| 超长单词（宽度 > max_width） | 保持完整，可能超出边界 |
| 连续空格 | 每个空格都显示并更新位置 |
| 换行符 `\n` | 强制换行到下一行起始位置 |
| 超出高度限制 | 停止显示 |

### 3. 性能优化

#### 优化措施
- **单词宽度计算**：O(n) 时间复杂度，n 为单词长度
- **避免重复计算**：每个单词只计算一次宽度
- **内存开销**：仅增加少量局部变量

#### 性能影响
- 单次调用增加约 10-20% 的计算时间
- 对于嵌入式系统可接受
- 显示效果提升显著
