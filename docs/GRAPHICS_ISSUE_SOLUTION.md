# SSD1680 电子纸显示问题解决方案

## 问题概述

在 ESP32-S3 平台上使用 SSD1680 三色电子纸显示屏时，遇到了图形显示异常问题。

## 问题现象

1. **全屏红色显示**：整个屏幕显示为红色，而不是预期的白色背景
2. **图形错位**：绘制的图形出现在错误的位置
3. **重影/残影**：右侧出现重复的图形图案和虚线痕迹

## 问题分析与解决方案

### 1. 红色显存逻辑错误

**问题**：
- SSD1680 红色显存的数据逻辑与预期不符
- 原始代码认为 0xFF=不显示红色，0x00=显示红色
- 实际上需要对红色数据进行取反

**解决方案**：
```c
// 写入红色显存时，对数据进行取反
static uint8_t s_red_temp[EPD_BUFFER_SIZE];
memcpy(s_red_temp, buffer_red, EPD_BUFFER_SIZE);
for (int i = 0; i < EPD_BUFFER_SIZE; i++) {
    s_red_temp[i] = ~s_red_temp[i];  // 取反
}
epd_write_data_batch(handle, s_red_temp, EPD_BUFFER_SIZE);
```

### 2. 坐标系统映射错误

**问题**：
- 用户坐标系 (296×152) 与 SSD1680 内部显存坐标系 (152×296) 映射不正确
- SSD1680 的物理 X 轴方向与用户坐标系相反（从右到左）

**解决方案**：
```c
// 用户坐标 (x_user, y_user) → 内部坐标 (internal_x, internal_y)
// 用户 X (水平 0-295) → 内部 Y (行号 0-295)，不反转
// 用户 Y (垂直 0-151) → 内部 X (列位 0-151)，需要反转
*internal_x = (canvas->internal_width - 1) - user_y;  // 151 - user_y
*internal_y = user_x;                                  // user_x
```

### 3. 显存地址计算错误

**问题**：
- 像素地址计算公式错误
- 原始代码使用了错误的地址计算顺序

**解决方案**：
```c
// 正确的地址计算公式
// addr = row * width_bytes + col_byte_offset
byte_addr = (internal_y * canvas->width_bytes) + (internal_x / 8);
```

## 技术要点

### SSD1680 显存布局
- **分辨率**：296 × 152 (宽 × 高)
- **内部显存**：152 位宽 × 296 行 = 5624 字节
- **每行字节数**：152 ÷ 8 = 19 字节
- **总字节数**：296 × 19 = 5624 字节

### 颜色模型
- **黑白显存**：0 = 黑色，1 = 白色
- **红色显存**：经过取反后，0 = 显示红色，1 = 不显示红色

### 坐标系统
- **用户坐标**：X(0-295), Y(0-151) - 以左上角为原点
- **内部坐标**：X(0-151), Y(0-295) - 映射到显存布局

## 修复验证

修复后，几何图形测试能够正确显示：
- ✅ 边框矩形（黑色）
- ✅ 对角线（黑色）
- ✅ 实心矩形（红色）在正确位置
- ✅ 空心圆（黑色）
- ✅ 实心圆（红色）

## 注意事项

1. **DMA 内存**：SPI 传输后避免立即调用 malloc/free
2. **缓冲区管理**：使用设备句柄中的 DMA 缓冲区
3. **显存同步**：确保黑白和红色显存数据同步
4. **坐标转换**：仔细验证用户坐标与内部坐标的映射关系
